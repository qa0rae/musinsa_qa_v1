# 무신사 Web QA 사이드 프로젝트

실제 무신사 웹 서비스를 분석하고, 주요 사용자 흐름을 E2E 시나리오로 검증하는 QA 사이드 프로젝트

## 프로젝트 목표

1. 무신사 서비스와 웹 페이지의 주요 사용자 흐름을 분석한다.
2. E2E 시나리오를 따라가며 각 기능과 위험을 분석하고, 그에 맞는 테스트 전략을 세운다.
3. 테스트 전략에 따라 테스트 케이스(TC)를 작성하고, 적합한 시나리오를 자동화한다.

## 초기 테스트 범위

**상품 검색 → 검색 결과 → 필터·정렬 → 상품 상세 → 옵션 선택 → 장바구니 → 결제 진입**

초기에는 이 흐름을 중심으로 기능을 분석하고 테스트한다. 범위와 우선순위는 분석 결과에 따라 조정할 수 있다.

## 진행 방식

1. **서비스 분석**: 화면과 실제 사용자 흐름을 확인하고, 확인된 사실과 가정을 구분한다.
2. **기능·위험 분석**: 시나리오에 포함된 기능과 실패 시 영향을 분석한다.
3. **테스트 전략 수립**: 테스트 범위, 우선순위, 테스트 기법과 확인 방법을 정한다.
4. **수동 테스트 및 TC 작성**: 전략을 바탕으로 사전 조건, 절차, 기대 결과를 구체화한다.
5. **자동화**: 안정적이고 반복 가치가 높은 시나리오를 Playwright로 자동화한다.

## 테스트 원칙과 범위의 한계

- 공개된 화면과 응답에서 확인한 사실, 추정, 미확인 사항을 구분한다.
- 공식 요구사항을 확인하지 못한 동작은 근거 없이 Pass/Fail이나 결함으로 단정하지 않는다.
- 실제 서비스의 상품, 가격, 광고, 응답 데이터는 시점에 따라 달라질 수 있으므로 실행 날짜와 조건을 기록한다.
- 실제 주문 생성이나 결제 승인 등 금전 거래는 테스트 범위에서 제외한다.
- 이 프로젝트는 개인으로 진행하는 프로젝트이며 무신사와 제휴·소속 관계가 없다.
